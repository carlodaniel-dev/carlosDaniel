## ✨ Características

* ⚡ Construido con **Astro** para ofrecer un sitio rápido y optimizado.
* 🎨 Diseño personalizado con **Tailwind CSS v4**.
* 📱 Diseño **responsive** para móvil, tablet y escritorio.
* 🧭 Navegación adaptada a diferentes tamaños de pantalla.
* 🖼️ Galería horizontal de proyectos con navegación responsive.
* 📄 Secciones de **Experiencia, Proyectos y Sobre mí**.
* 📬 CTA de contacto mediante **correo electrónico y WhatsApp**.
* 💬 Formulario de contacto para generar mensajes personalizados en WhatsApp.
* ♿ Consideraciones de accesibilidad y soporte para `prefers-reduced-motion`.
* 🎯 Diseño orientado a presentar experiencia profesional y captar oportunidades laborales y freelance.

## 🚀 Instalación y desarrollo

Clona el repositorio:

```bash
git clone https://github.com/carlodaniel-dev/carlosDaniel.git
```

Accede al proyecto:

```bash
cd carlosDaniel
```

Instala las dependencias:

```bash
npm install
```

Inicia el servidor de desarrollo:

```bash
npm run dev
```

El proyecto estará disponible en:

```text
http://localhost:4321
```

### Un cambio importante

También corregí algo que estaba desactualizado en tu README:

Antes tenías:

```text
public/
└── img/
```

pero actualmente tus imágenes están realmente en:

```text
src/assets/img/
```

Además, ya no aparecen en el proyecto actual:

```text
Badge.astro
SocialPill.astro
TitleSeccion.astro
```

por eso no deben aparecer en la estructura del README.

### Commit

Como aquí estamos **actualizando documentación**, usaría:

```text
docs(readme): actualizar documentación del portfolio v2
```

Este sí es claramente un `docs`, mientras que la limpieza anterior sigue siendo:

```text
refactor(cleanup): eliminar archivos y assets no utilizados
```

Así tu historial queda bastante coherente:

```text
feat(about): rediseñar sección sobre mí
feat(contact): agregar CTA y formulario de contacto por WhatsApp
feat(footer): rediseñar pie de página del portfolio
refactor(cleanup): eliminar archivos y assets no utilizados
docs(readme): actualizar documentación del portfolio v2
```

Ese orden cuenta muy bien la evolución de la V2: **rediseño → funcionalidad → limpieza → documentación**.
